## 1. 一度だけやること

### ① Apps Script に v2 のファイルを足す

1. https://script.google.com を開き、これまで使っているプロジェクト（data.json を作っているもの）を開く
2. 左の「ファイル」の＋ →「スクリプト」→ 名前を **`intake-v2`** にする
3. `tools/intake-v2.gs` の中身を**全部**コピーして貼り付け → 保存（💾）

### ② update-data.gs を貼り替える

1. 同じプロジェクトの `update-data`（または `コード.gs`）を開く
2. 中身を全部消して、`tools/update-data.gs` の中身を全部貼り付け → 保存

> 変えたのは3か所だけです。①1日4回の実行のいちばん最初に取込を走らせる ②data.json に `meta.intake` を載せる ③note台帳_base も読む。

### ③ Slack の通知先をつくる

1. Slackに **`#gokigen-取込`** チャンネルを作る（まだ無ければ）
2. https://api.slack.com/apps → Create New App → From scratch → ワークスペースを選ぶ
3. 左メニュー **Incoming Webhooks** → Activate を On → **Add New Webhook to Workspace** → `#gokigen-取込` を選ぶ
4. 出てきた `https://hooks.slack.com/services/...` をコピー
5. Apps Script の左下 **⚙ プロジェクトの設定** →「スクリプト プロパティ」→ プロパティを追加
   - 名前：`SLACK_WEBHOOK_URL`
   - 値：コピーしたURL
6. 保存

> **未登録でも止まりません**。通知が出ないだけで、アプリのバッジには全部出ます（「Slack通知が未設定です」とも出ます）。

### ④ 関数を上から順に1回ずつ実行する

Apps Scriptの上部にある関数の選択欄から選んで「▶ 実行」。**この順番で**。

| 順 | 関数 | 何をする | 目安 |
|---|---|---|---|
| 1 | `step0_backupLedgers` | 台帳フォルダの全ファイルをDriveの中に複製（削除しない） | 2〜5分※ |
| 2 | `syncSchemasToDrive` | schema/*.json をDriveの `schema` フォルダへ配る | 5秒 |
| 3 | `step2_migrateV1ToBase` | 日次スナップショットを各台帳_baseへ一括取込。元ファイルは `_v1アーカイブ`／`圧縮済み` へ移動（削除しない） | 1〜3分 |
| 4 | `runIntakeNow` | 取込箱をいま処理する（最初は空でOK。Slackに「🈳 取込箱は空」が出れば配線成功） | 10秒 |
**うまくいかないとき**：`step2_checkLedgers()` を実行すると、各台帳の**シート名と1行目の見出し**が一覧で出ます（読むだけで何も書き換えません）。「列がありません」と言われたら、まずこれを見てください。

> 2026-09-20に実際に出たエラーと直し方
> 「Udemy台帳_base に列がありません」→ **見出しが無かったのではなく、1枚目が「ダッシュボード」**で、台帳の実体は「台帳ログ」シートだった。v2が中身を見てシートを選ぶように直しました（ダッシュボードには1行も書き込みません）。
> 「経済台帳_base に列がありません: 記録日・通貨」→ 実物の見出しは `日付／区分／項目／数量・額面／評価額円／評価損益円／損益率／備考` で、**「記録日」は「日付」、「通貨」の列は元々無い**。別名で読み替え、「通貨」だけを見出しの右端に足すようにしました（既存の列はずれません）。
> どちらも `step2_migrateV1ToBase()` をもう一度実行すれば通ります（**何度実行しても二重になりません**）。

| 5 | `runNow` | data.json を作り直す | 1〜2分 |

※ 1の途中で「時間切れ」と出たら、**もう一度同じ関数を実行**してください。続きから進みます（何度やっても増えません）。

## 2. これからの毎日（v2の点呼手順）

Claude側の手順です。本人がやることは**これまでと同じ「スクショを送る」だけ**。

1. Slack `#gokigen-取込` を読む → ❌があれば理由を見て、その場で正しいJSONを作り直して再投入し、「昨日の取込NG1件、再投入しました」と1行報告する
2. スクショ／リミットレスを受け取る → **該当するスキーマを読む**（Driveの `schema/<台帳>.json`）
3. 取込JSONを **📥_取込箱** に書く（ファイル名は `intake_<台帳>_YYYY-MM-DD_HHMM.json`）
4. 書いたJSONを**読み返して3点検品**（①mimeTypeがapplication/json ②必須キー ③数値レンジ）
5. 点呼レス（体重ミニグラフ・次アクション・鉱脈候補）＋「**取込JSON検品OK**」の1行

**禁止**：自由文の台帳ファイルを作ること／台帳フォルダへ直接書き込むこと。
（GAS側も、台帳フォルダに置かれた新しいファイルは読みません）

台帳の名前は8つ：`gokigen` / `udemy` / `note` / `economy` / `limitless` / `places` / `teizan` / `eigyobu`

`eigyobu`（2026-09-26追加）＝営業部の物差し。毎月1日に代表が送るUdemy講師画面のスクショ2枚（パフォーマンス概要のUdemy Business部分／クーポン画面）から、前月のUB経由の内訳とクーポン別の購入数を書く。
行き先は GOKIGEN台帳フォルダの下の「営業部_物差し」フォルダの「営業部_物差し台帳_base」（直下ではないので update-data.gs は読まない＝アプリには出ない）。
Mac mini の `~/DTD/bin/eigyobu_monosashi.py` が 📦_取込済 の JSON を読み、`~/DTD/台帳/営業部_物差し.md` に写す。
追加したとき一度だけ：intake-v2.gs を貼り替え → `syncSchemasToDrive()` を1回実行（schema/eigyobu.json がDriveに配られる）。
